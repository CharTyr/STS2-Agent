## 2. 目标（玩家视角）

把「装上 Mod → 看 AI 打完一局」从「慢、贵、偶尔罢工、看不懂它在干嘛」变成「快、省、稳、看得懂、还打得更好」。
量化目标（以改造前 v0.17.0 同模型同类场景为对照；实机条件不足时以离线基准/模拟估算并注明）：

1. **速度**：自动游玩一场普通战斗的墙钟时间下降 ≥ 50%；整局（同楼层数）时间下降 ≥ 50%。
2. **成本**：每层模型请求数下降 ≥ 50%（整回合规划 + 小事自动处理 + 视觉按需）；单次请求 token 不上升。
3. **质量**：模型拿到确定性的战斗算术（来袭伤害、需挡格挡、每张牌对每个敌人的真实伤害、可斩杀判断）；
   离线决策基准不退步，新增计算器相关用例全部通过。
4. **稳定**：可自愈的失败（流式参数截断、索引过期、单次网络抖动、模型给出非法动作）不再直接停机；
   「连续 3 次失败停机」只在真正不可恢复时出现。
5. **观看体验**：玩家在游戏画面上直接看到 AI 正在做什么（要出的牌、目标、本回合计划、一句话理由、加速档位、
   暂停热键）；一局结束有总结卡。
6. **性能**：Mod 不再造成可感知的掉帧；无人订阅事件流时不做整份状态构建。
7. **接入**：外部 MCP 智能体（两套 MCP 面）同样获得整回合规划与战斗计算器，并且不破坏现有客户端。

## 3. 范围（工作流 W0–W11，细节见 design.md 同名章节）

| 编号 | 工作流 | 玩家能感受到的变化 | 优先级 |
| --- | --- | --- | --- |
| W0 | 地基 | 无（分支、开关、为超预算文件腾位置、基线测试） | 必须先做 |
| W1 | 游戏加速（Turbo） | AI 自动游玩时游戏动画自动切到游戏自带的「快速/极速」档，暂停或结束时恢复玩家原设置 | P0 |
| W2 | 小事自动处理（Autopilot） | 只有一个合法选择、确认弹窗、只剩结束回合等无需判断的步骤不再问模型，零花费、瞬间完成 | P0 |
| W3 | 整回合规划（Turn Plan） | 模型一次给出整回合的出牌序列，Mod 逐步校验执行，局面意外变化时自动中止并重新决策 | P0 |
| W4 | 战斗算术 | 模型（含快速判断）与外部智能体拿到精确战斗算术（来袭总伤、需挡多少、每张牌对每个敌人的真实伤害、能否斩杀），减少漏挡、错过斩杀、打错目标 | P0 |
| W5 | 策略大脑 | 选牌/商店的稀有度类型价格与牌组统计、地图路线建议、跨局战绩事实摘要 | P1 |
| W6 | 省钱瘦身 | 每个决策从平均 2.17 次请求降到约 1 次；游戏内提示词去掉与当前决策无关的状态（约 −23% token）；截图按需；显示缓存命中率 | P0 |
| W7 | 自愈与兼容 | 失败按原因处理（网络抖动多等几次、窗口在后台不算失败）；记住服务商能力并自动选请求方式；可补全的动作自动补全；停机说人话 | P0 |
| W8 | 观看体验 | 修复「配置成功后下次打开面板消失」；标题行说人话；卡住时给提示；游戏画面内 AI 意图层（要出的牌、目标连线、理由气泡、横幅）；局末成绩单；暂停热键 | P0 |
| W9 | 性能 | 等待时不再每帧整份构建状态（AI 打牌掉帧的主因）；回合快照轻量化；事件流自适应；悬浮窗刷新更省 | P0 |
| W10 | 联机与 MCP | 队友同样受益（小事自动处理、整回合规划）；两套 MCP 面提供整回合规划与计算器 | P1 |
| W11 | 文档与验收 | project-map / api.md / openapi / CHANGELOG / README / 实机报告同步 | 必须 |

不在范围（明确不做）：
- 自研 STS2 战斗模拟器 / MCTS（工作量与正确性风险过大；W4 只用游戏自身的数值预览做「当前局面算术」）。
- 无头/脱离渲染器运行游戏（sts2-cli 路线）。
- 修改游戏规则或给 AI 作弊信息（例如偷看抽牌堆顺序）；**公平原则：AI 只用玩家可见的信息**。
- 发版、改版本号、上传工坊（用户决定先不发）。

## 4. 约束（来自仓库规则，违反会被测试或评审拦下）

- 游戏/Godot 对象只能在游戏线程访问（`GameThread.InvokeAsync`，从 Agent 回合发起时带取消令牌与期限）。
- 游戏路径中的 await 必须有界（`GameTaskBoundingContractTests`）。
- 单一动作面（ADR 0001）：动作只在 `EnumerateAvailableActions` 里变得可用；整回合规划是对既有动作的编排，不新增游戏动作。
- 两套 MCP 面（ADR 0002）：新工具/新参数在原生 `NativeMcpServer*` + `AgentTools` 与 Python `server.py` 两边都加，`test_native_tool_alignment.py` 双向比对。
- API 向后兼容：只增字段不删字段；新字段在 `docs/api.md` 有表格行（`api-facts` 闸门）；compact 视图结构变化要升 `AgentViewVersion`。
- 动作永不自动重放（`outcome_unknown` 后最多一次对账）；一次请求只记一次账；预算在发请求**前**检查。
- 本地化：中文字符串即键 `Loc.T("中文")`，每个调用点在 `Localization/Loc.Strings.*.cs` 有英文。
- 文件行数棘轮：默认每个源文件 ≤ 1000 行；`AgentLoop.cs` 已是 1000/1000，必须先把代码移出再加。Python 默认 ≤ 700 行（`server.py` 699、`client.py` 696）。
- 新增/改名源文件同步 `docs/project-map.md`（`ProjectMap.*` 测试）；依赖游戏的新 `.cs` 登记到 `SourceCoverageTests.KnownUncompiledSources`；纯逻辑放 Godot 无关的 `*Policy.cs` 并编进离线测试工程。
- 密钥永不入日志/导出/入库。
- 不碰用户正在玩的游戏；部署 DLL 前确认游戏已关闭。

### 5.2 分工作流（每条都要有离线测试；标 ★ 的还要实机观察）
- W1 ★ 自动游玩开始时切到加速档、暂停/停止/离开对局/退出游戏时恢复玩家原档位；联机局默认不超过「快速」档；检测到 SpeedX 等加速 Mod 时不叠加；设置页可关、可选档位。
- W2 ★ 无判断步骤零模型请求完成，并在决策记录里标明来源「自动处理」与理由；任何涉及取舍的选择（选牌、路线、商店、事件、药水）绝不自动做。
- W3 ★ 一次模型请求可执行多步；每步执行前用最新状态校验；牌用稳定的战斗卡牌 id 定位；出现抽到新牌/目标死亡/能量不足/屏幕变化等偏离时停止剩余步骤并回到正常决策；每一步都进决策记录，费用只记在第一步。
- W4 compact 战斗视图新增 `combat.threat`（来袭总伤、需挡、挡后剩余、结束回合后 HP、致命）与 `hand[].vs`（每张牌对每个敌人的精确伤害与是否击杀）、`kill_options`/`max_block` 估算；数值来自游戏自身预览；`docs/api.md` 有行；`AgentViewVersion` 13；离线测试覆盖算术；★ 抽查与画面一致。
- W5 奖励/商店带稀有度、类型、数字价格与牌组统计；地图可选 ≥2 时给路线统计与建议；跨局战绩只存事实、有条数与长度上限、可清空。
