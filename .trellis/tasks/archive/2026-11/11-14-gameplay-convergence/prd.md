# 收敛 AI 游玩 skill 与决策工具流程

## 目标

在 v0.113.0 适配完成后收敛 skill、工具和使用方式，减少无效读取、矛盾指导与操作等待，使 AI 游玩时决策更清楚、动作更顺畅。用户于 2026-11-14 要求继续推进，指定探索收集使用 `gpt-6-luna`、代码落实使用 `gpt-6.1-terra`；推理强度沿用 max。

## 已确认事实

- 游戏内与外部 MCP 两条入口共用动作服务；已有 guided 工具、紧凑状态、场景指导、整回合计划、Autopilot 和动作后状态复用。
- `SKILL.md` 混合连接配置、共享合同、诊断、日志与规划器用法；共享合同会嵌入游戏内提示词。
- 应优先复用现有动作和数据，不增设重复工具；公开 API 保持兼容，未知动作结果不得重放。

## 要求

1. 固定本项目 Codex 代理的模型分工，核实派生角色已加载指定模型。
2. 以只读证据识别 skill/提示词和正常 `decide → act → wait` 的重复、歧义、断点，形成兼容的首批收敛方案。
3. 明确正常游玩主循环、整回合计划、按需知识查询与失败恢复；实现及检查由 Terra 承担。
4. 维护 changelog、相关文档和规格；不重复执行已有检查。
5. 修复独立复核已复现的计划结果误分类：同时含 `status=outcome_unknown` 和 `error` 的生产载荷，必须仍报告 `plan.stop_reason=outcome_unknown`，不能伪装成确定拒绝；保留不重放与停止后续步骤。

## 验收

- 代理配置可解析，实际派生接口可核验，未核实不声称使用指定模型。
- 默认游玩路径说明明确，不与整回合计划、状态复用或游戏内新鲜状态注入矛盾。
- 普通游玩不因指导而强制重复读取已有状态或已提供的静态说明。
- 涉及的 C# / Python 行为与文档同步，公开工具及参数兼容，必要的回归检查通过。
- 明确区分离线与实机证据，不宣称未经测量的胜率提升。

## 不在本轮

移除公开工具、改变游戏合法性规则、重做 UI、引入新规划器或知识库、模型服务商调用、实机对局与发布。

## 环境修复及提交授权（用户追加）

用户已批准按清单本地提交，并要求处理剩余环境失败。修复测试对临时目录位于仓库外的隐含依赖，调查 Windows HttpListener 句柄无效的能力边界；不得改产品断言或静默吞掉真实失败。确实不可用的系统能力应显式报告跳过及原因，不能记为通过。验证后提交本轮工作及必要环境测试修复，不 push、合并或发布。
