# 实施与验证

1. 审阅获批后从最新可核对的 `origin/dev` 在独立分支/worktree 实施，保留主工作区里的其他改动。从 `[原监听错误 6 → TCP 后备 /health 成功]` 的独立探针建立红绿和诊断记录。
2. 在无外部运行时依赖的产物布局上先做隔离 Godot 装载验证。保留可用实现的装载/打包证据，再开始正式接线；不能加载时先停下确认可行方案，不扩大部署权限。
3. 以真实监听与注入故障的回归为先，覆盖正常、错误 6 切换、两者失败、固定端口不可用、错误传播；确保单一 Router 下保留 REST、原生 MCP、SSE、请求限制和安全边界。更新包完整性、Mod 项目地图、架构说明与 Unreleased。
4. 重跑 Mod 编译、C# 与 Python 套件、项目门禁、打包检查。在隔离游戏中记录失败前后、监听器日志、DLL 哈希和实际响应；先确认正常 API，再邀请无 Key 的外部队友并经原生 MCP 出牌。DSH 连接实测与协议直测单列，未验一律标明。最后验证故障时游戏内面板与按钮降级。不发布、不操作正在玩的实例、不调用付费模型。
